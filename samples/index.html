Mintx AssistantTest scenarios

How to test

  1. Start the server: .\start.ps1 for real answers (Ollama), or .\start.ps1 -Mode dummy for the fast offline model.
  2. Load the assistant folder in chrome://extensions (Developer mode → Load unpacked).
  3. Open a scenario page below, press Alt+M, type the question, and compare with Expect.
  4. In every run, expand the privacy card and open What the model sees: that text is the only page content that leaves your browser.

Automated version of the same checks: python assistant/test/scenarios.py

Page scenarios

1 · Support ticket

 mixed PIIIndian IDscoreference

Ask: “Draft a short reply to the customer and list what you need from finance.”

Expect: about 17 values protected: names, email, phone, card, Aadhaar, PAN, DOB, UPI, IBAN, API key, IP, address. “Priya”, “Sharma” and “Priya Sharma” all share one placeholder. The words “Aadhaar” and “PAN” stay visible. The password field is never read. Real values reappear in the answer, highlighted yellow.

2 · Developer build log

 secretsentropyutility

Ask: “Why did this build fail and how do I fix it?”

Expect: the AWS key, GitHub token, database password, JWT, the engineer's name and email are masked. The commit hash, request UUID, version numbers and the error message stay readable, so the model can still diagnose the failure.

3 · Patient intake form

 form fieldspassword never read

Ask: “Check this form for missing or inconsistent details.”

Expect: the typed form values are read and masked (name, DOB, both phones, email, address, emergency contact). “Migraine#2026” from the password field never appears anywhere. Symptoms are not identifiers, so they are kept: a good point to discuss for health data.

4 · Public news article

 precisionover-masking

Ask: “Summarize this article in three bullet points.”

Expect: dates, figures and percentages are untouched. Organizations and cities may be masked by the NER layers: that is the privacy-versus-utility trade-off. Try Relaxed in settings, or Review before sending and click Share.

5 · Prompt injection

 securityexfiltration

Ask: “Summarize my order.”

Expect: the invisible display:none instruction is never read. The tiny white “SYSTEM OVERRIDE” text is read, but the model only has placeholders, so even if it obeys it cannot reveal real data. The answer never loads the attacker's image link (the renderer has no images or links).

Feature scenarios

  1. Follow-up memory · after scenario 1 ask “What is her phone number?”. The same [PHONE_1] is reused across turns.
  2. Human review · tick Review before sending, ask anything on the ticket, click Share on the email and watch What the model sees change; then Send or Cancel.
  3. Server egress guard · settings ⚙ → untick Rules + checksums, ask on the ticket. The server blocks the request (unmasked EMAIL, CREDIT_CARD…) and nothing reaches the model.
  4. Synthetic surrogates · settings → Synthetic surrogates, then + (new chat). The model sees “Alex Morgan”, “user1@example.com”; you see the real values.
  5. Sensitivity · on the build log compare Strict and Relaxed: low-confidence items move between masked and the “left unmasked” list.
  6. Selection · select one paragraph, right-click → Ask Mintx about the selection.
  7. Show on page · after any answer, click Show on page to highlight what was detected.
  8. Unreadable page · ask on chrome://extensions: Mintx answers without page context instead of failing.
  9. Server down · stop the server: the status pill turns red and the chat shows a clear error.
